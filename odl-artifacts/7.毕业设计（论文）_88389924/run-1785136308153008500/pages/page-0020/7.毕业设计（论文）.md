# 3 需求分析

- 3.1 功能需求分析 本系统旨在为医疗机构及个人用户提供便捷的 DR 筛查服务，以轻量化、高效率易

操作为核心目标，功能需求围绕用户使用全流程展开，具体如下：

用户权限管理功能。支持用户注册、登录、密码修改，区分管理员与普通用户两种 角色。管理员可查看并管理全部用户信息及筛查记录，普通用户仅能操作个人账号。

眼底图像筛查功能。支持单张眼底图像上传筛查，兼容 JPG、JPEG、PNG 常见格 式。支持批量眼底图像上传筛查，单次最大处理量不低于 50 张，满足批量筛查场景。

筛查结果展示功能。输出二分类结果（正常眼底/糖尿病视网膜病变），显示模型预 测置信度，并基于置信度完成病变程度分级，分为正常、轻度、中度、晚期。

历史记录管理功能。每次筛查记录自动保存，包含图像信息、诊断结果、置信度、 筛查时间。支持历史记录查询、追溯及导出（CSV 格式），方便数据统计与复诊参考。

- 3.2 性能需求分析 在构建这套糖尿病视网膜病变筛查系统时，推理速度、资源占用和运行稳定性是衡


量其临床实用价值的三项核心性能指标。结合眼底医学影像分析的特点以及基层医疗机 构硬件条件有限的实际情况，系统需要满足以下性能要求：

- （1） 推理速度。实时性直接影响基层筛查效率，在社区义诊、基层门诊或者移动

筛查车上，系统需在较短的时间内完成一张眼底照片从上传到给出诊断的过程，对性能 的要求是：每张眼底图平均推理时间不超过 30ms，每张端到端响应时间（包括预处理 以及后处理）不超过 3s。

- （2） 资源占用。由于大部分基层医疗机构硬件条件较差，模型需尽量小，以便于

部署，对模型的要求是，模型参数量不超过 5M，模型文件大小不超过 20MB，在无独 立显卡普通 PC 或者嵌入式设备上可以进行推理，做到低成本、易部署的轻量化运行。
