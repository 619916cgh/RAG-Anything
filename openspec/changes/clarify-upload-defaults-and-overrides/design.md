## Context

知识库详情页将 KB 默认和一次上传的分块策略绑定到同一个 React 状态。加载或保存 KB 默认会改写上传选择，两个相邻控件也无法说明优先级。上传 API 已有空策略省略 query 参数的兼容行为；后端会在持久化前解析不可变任务快照。

## Goals / Non-Goals

**Goals:**
- 让常规上传明确继承 KB/个人/平台的有效策略。
- 让临时策略成为显式、一次提交的覆盖，并在服务端接受请求后清除。
- 让批量内每个文件从同一原始请求覆盖独立解析快照。

**Non-Goals:**
- 不新增、删除或修改上传 API、数据库 schema、历史任务快照或全局设置优先级。
- 不恢复图片、表格、公式或视频的用户开关。

## Decisions

- 上传区以空字符串表示无覆盖。现有 API 客户端仅在非空时附加 `chunking_strategy`，因此无需新增 wire contract。
- KB 设置草稿继续拥有持久默认；上传区在组件内拥有 `temporaryChunkingStrategy` 和展开状态。KB 加载、保存与切换不得写临时值。
- 摘要使用服务端返回的 effective 值和 field source。`knowledge_base_setting`、`user_setting` 与其余平台/系统来源分别使用准确文案。
- 临时覆盖在单文件或批量请求 Promise resolve 后清除并收起；Promise reject 时保留。清除使用提交时捕获的值，避免较早请求清除用户后来选择的新值。
- 批量路由保留不可变 `requested_strategy`，每个文件局部读取其 `resolved_strategy`；禁止将解析结果回写到下一个文件的请求参数。

## Risks / Trade-offs

- [用户看不到选择器] → 摘要始终说明当前策略，并提供带展开状态的“临时修改”按钮。
- [部分批量结果] → HTTP 成功即代表该次提交已被服务端接受，按已批准语义清除覆盖；失败的本地文件仍可重新选择策略后重试。
- [旧客户端] → 后端继续接受空或明确策略参数，优先级与持久快照格式不变。

## Migration Plan

部署前运行前端和上传快照回归测试。变更只影响新提交时是否携带策略参数；回滚前端即可恢复原界面，已入队任务保持已有快照。
