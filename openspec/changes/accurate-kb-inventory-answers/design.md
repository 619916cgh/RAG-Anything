## Context

知识库页面和智能体分别从文档状态与检索上下文得出数量。后者是相关性排序的子集，不能作为库存事实；前者又把标签补处理覆盖为整体处理中，不能表达内容是否已可检索。

## Goals / Non-Goals

**Goals:**

- 由单一、受权限保护的服务生成按类型和状态聚合的文档库存。
- 让高置信度的中文数量问题在智能体路由层使用该服务，完全绕过 RAG 与 LLM。
- 将内容入库状态和标签补处理状态分开提供给文档列表与库存回答。

**Non-Goals:**

- 不改变普通 RAG 的召回数量、排序、引用或视频分段。
- 不自动修复、重传、删除或重建历史文档；生产单文档恢复保持人工受控。
- 不新增物化计数、数据库迁移或未授权跨知识库统计。

## Decisions

- **抽取共享库存服务。** 该服务复用文档摘要的去重和运行时任务合并规则，返回不含文件名或路径的类型/状态计数。避免智能体调用路由或重新实现状态语义。
- **以内容可用性定义可检索。** `content_ready` 且底层内容状态为 `processed`/`completed` 的文档计入可检索；标签为 pending/running/retry 时另计为标签补处理，不从可检索数扣除。标签终态失败保留内容可检索性并报告为标签失败警告。
- **使用高精度规则而非 LLM 分类。** 仅当问题含知识库/资料/文档库存对象、数量意图及可识别文件类型或文档泛称时进入统计分支；“视频中有多少零件”等缺少库存对象的问题保留 RAG。
- **保持 SSE 与会话契约。** 统计分支发出正常 token/done 事件并保存用户和助手消息，附加仅供前端渲染的库存元数据；不伪造语义引用。
- **公开只读库存端点。** `GET /knowledge/inventory` 使用现有 KB 访问依赖，供 UI、诊断和智能体共享；返回总数、各类型及状态分解，不返回单个文件数据。

## Risks / Trade-offs

- [状态来源存在历史不一致] → 使用与文档列表一致的合并/去重函数，并在测试中覆盖持久文档、运行时任务和重复文件。
- [意图规则误拦截内容问题] → 规则要求库存对象和数量短语同时出现；无法高置信识别时不拦截。
- [标签任务长期未收敛] → 对外显示“已可检索，标签处理中”，生产恢复先核验任务归属和持久内容，再执行单任务重试。
- [并发工作区改动] → 不重构既有权限、智能体模式或文档摘要接口，只新增局部服务和调用点。

## Migration Plan

1. 发布代码前运行聚焦单元/API/SSE 测试和前端状态测试。
2. 通过受控发布部署，不执行迁移或批量重建。
3. 在生产只读比对库存接口与页面列表；确认缺失编号的原始上传与任务归属。
4. 仅在备份和归属核验完成后，受控恢复单个标签任务，并复测统计回答。
5. 回滚只需回滚应用版本；库存接口为新增只读接口，不持久化新数据。

## Open Questions

- 无。用户已确定返回总数、可检索数、处理中/失败数，并覆盖所有知识库与文件类型。
